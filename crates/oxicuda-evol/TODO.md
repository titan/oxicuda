### oxicuda-evol TODO

Evolutionary & Genetic Algorithms for OxiCUDA — a pure Rust collection of population-based
optimisers (GA, CMA-ES, DE, PSO, ACO), multi-objective methods (NSGA-II, MOEA/D), and
neuroevolution (NEAT). Part of [OxiCUDA](https://github.com/cool-japan/oxicuda) (Vol.48).

(C) 2026 COOLJAPAN OU (Team KitaSan)

## Implementation Status

**Actual: 4,748 lines / 3,686 SLoC (27 files)** — covers GA building blocks, CMA-ES, DE,
NSGA-II, MOEA/D, NEAT, PSO, ACO, multi-objective metrics, and 7 PTX kernels × 6 SM
versions. All algorithms are implemented end-to-end in pure Rust with no external
linear-algebra or RNG dependencies.

|----------|------------------|--------|

Throughput targets assume warm GPU contexts; cold-start overhead is absorbed by the
`oxicuda-driver` lazy loader.

## Notes

- The PTX kernels in `ptx_kernels.rs` are deliberately written as string concatenation
  rather than `format!` to keep the generated PTX register names stable across SM versions
  and to satisfy `clippy::format_push_string` policy.
- All RNG inside both host and device code uses `LcgRng` with the MMIX multiplier; the
  bit-32 boolean trick avoids the period-2 defect of bit 0.
- The `EvolHandle` is the central entry point; each algorithm accepts it and a `&mut LcgRng`
  for reproducibility — the same seed produces the same evolutionary trajectory.
- `evaluate<F>` takes a closure so any user-defined fitness function works without
  requiring a registered trait object.
