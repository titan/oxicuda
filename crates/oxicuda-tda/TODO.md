### oxicuda-tda TODO

Topological Data Analysis for OxiCUDA — a pure Rust toolkit for persistent homology,
Vietoris-Rips filtrations, persistence diagrams, the Mapper algorithm, witness
complexes, and standard TDA metrics (Betti numbers, persistent entropy, persistence
landscapes). Part of [OxiCUDA](https://github.com/cool-japan/oxicuda) (Vol.49).

(C) 2026 COOLJAPAN OU (Team KitaSan)

## Implementation Status

**Actual: 53 source files** — implements the standard ELZ-2002 persistence reduction
over Z_2 (plus a host-side chunk-parallel reducer that is bit-identical to it), exact
bottleneck and Wasserstein-1 distances, landscape distance, Mapper with single-linkage
clustering, lazy-witness complex with maxmin landmark sampling, two-parameter persistence
(rank invariant / Hilbert function), Stable Mapper bootstrap, and 7 + 3 PTX kernels
× 6 SM versions.

## Performance Targets

| Workload | Size | Target |
|----------|------|--------|
| Pairwise Euclidean distance | n = 4096 in dim ≤ 64 | bandwidth-bound (≥ 90% theoretical) |
| Vietoris-Rips filtration enumeration | n = 1024, max dim = 2 | edges + triangles ≤ 50 ms on sm_80 |
| Boundary matrix column reduction | ~50K simplices | within 2× CPU baseline (PHAT / Ripser) |
| Bottleneck distance | diagrams with ≤ 1000 pairs | exact within 10 ms |
| Wasserstein-1 distance | diagrams with ≤ 500 pairs | exact (Hungarian O(n³)) within 100 ms |
| Mapper construction | n = 4096, cover = 25, overlap = 0.3 | ≤ 100 ms total |

The persistence reduction is currently a CPU-side ELZ implementation; the
`boundary_reduce` PTX kernel is a stub awaiting integration with a GPU column-reduction
pass (chunk-based pivot lookup with shared-memory hashing).

## Notes

- The PTX kernels are deliberately written as string concatenation rather than `format!`
  to keep generated register names stable across SM versions.
- `BoundaryMatrix` stores each column as `Vec<usize>` of row indices (Z_2): sparse
  enough for typical filtrations and compatible with XOR-style column addition.
- Both `bottleneck_distance` and `wasserstein_1` use the standard reference algorithms
  (binary-searched bipartite matching and the Hungarian method respectively) so they
  match every TDA library that follows Edelsbrunner-Harer.
- `Filtration` always stores simplices sorted by `(value, dim, lex)` so the boundary
  matrix can be built directly without resorting.
- 0.5.0: `homology/cohomology.rs` and `homology/reduction.rs` each had a redundant
  is-empty-check-then-panic pattern eliminated (restructured to `while let` loops) --
  an internal code-quality fix with no algorithm or behavior change.
